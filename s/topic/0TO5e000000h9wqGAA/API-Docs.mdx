The **Latchel Partner API** lets you connect your own systems to Latchel so you can read and update your vendors, properties, residents, work orders, invoices, and more.

<Tip>
  **Manage your own setup.** With the API you can add owners, portfolios, and vendor companies and assign vendors to properties or portfolios yourself, so updates happen right away. It's optional: our team is always happy to handle these for you.
</Tip>

## Getting Started

1. **Generate an API key** from your Latchel dashboard. See [How to Generate an API Key](/s/topic/0TO5e000000h9wqGAA/How-to-Generate-an-API-Key). Include the key in the header of every request.
2. **Test your key** by calling `GET /me`. A successful response confirms your key is working.
3. **Build and test** against the sandbox before going live.

| Environment | Base URL |
| --- | --- |
| Production (live data) | `https://papi.latchel.com/v1` |
| Testing / development | `https://latchel-demo.com/v1` (requires a development API key; data isn't guaranteed to persist) |

## Good to Know

- **Keep your API key private.** API keys have full access to your account. Re-generating a key immediately invalidates the old one, so update any integrations that use it.
- **Rate limits:** 600 requests per API key, per 10 minutes. If you go over, you'll receive a `429` response with a `Retry-After` header telling you when to try again.
- **Pagination:** list endpoints return one page at a time. Use `page` to move through pages and `per_page` (1 to 500, default 10) to set the page size.
- **Only pull what changed:** `GET /properties`, `GET /tenants`, and `GET /properties/{property_id}/tenants` accept `updated_at_start_date` to return only records changed since that time. Save the time each sync starts and pass it on the next one.
- **Webhooks:** want Latchel to notify your system when work orders, portfolios, or residents change instead of polling? See our webhook documentation in the Help Center (search "Webhooks").
