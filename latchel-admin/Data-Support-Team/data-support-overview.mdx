The Data Support (DS) Team keeps every property manager's (PM) Latchel account accurate, healthy, and ready for work orders. We're part of Product Support, and we handle the account changes, data corrections, and system-specific updates that need deep product knowledge.

    We live Latchel's core values in our day-to-day work:

    - **Customer Obsession:** we treat every account update as if the PM's residents are waiting on it, because they are.
    - **Continuous Improvement:** we look across tickets for trends and unhealthy accounts, and we fix the root cause, not just the symptom.
    - **Develop Extraordinary Teams:** we document what we learn so anyone on the team can do the work confidently.
    - **Think Big:** we build tools and processes, like the Data Support Tool, that make bulk work faster and safer.

  <Accordion title="Our Responsibilities" defaultOpen icon="clipboard-list-check" iconType="duotone">
    | Area | What we own |
    | --- | --- |
    | **Account health and accuracy** | Properties, residents, owners, and portfolios match the PM's source of truth. |
    | **Account configuration** | Company, portfolio, and property settings, including service provider prioritization. |
    | **Onboarding data** | Loading and checking data for new accounts so they go live correctly. |
    | **Integrations and data migration** | Matching reference IDs, activating integrations, and cleaning up duplicates. |
    | **Data corrections** | Merging duplicates, fixing contact info, and reconciling active unit counts. |
    | **Help Center content** | Writing and updating help guides and newsletter articles on help.latchel.com. |
    | **Escalation** | Raising account and integration issues to the right owner, such as the CSM. |
  </Accordion>

  <Accordion title="Our Tasks" defaultOpen icon="list-check" iconType="duotone">
    Most of our work comes in through the **Account Update Request** Typeform in **#data-support-requests**, which creates an Assembly (ASM) ticket in the Data Support team space.

    **Property and resident updates**
    - Bulk import new properties and residents
    - Enable, disable, or reactivate properties and residents
    - Update resident contact info, move-in, and move-out dates
    - Merge duplicate properties and residents
    - Update critical notes, home warranty notes, and work order budget limits
    - Audit active unit counts (Active Unit Adjustment requests)

    **Portfolio and owner updates**
    - Create portfolios and assign properties to them
    - Create owners, update owner contact info, and set owner approval settings

    **Service provider updates**
    - Add new service providers and assign them to PMs
    - Update prioritization, skills, response buffer, VIP status, and invoice collection

    **Integrations**
    - Data migration projects (reference ID matching)
    - Integration activation
    - Failed work order sync and duplicate investigations

    **Recurring and partner work**
    - Optional Benefits audits for CPT (first two weeks of each month)
    - Recurring property and resident reports from specific PMs
    - Nomad and RentRedi preferred service provider requests

    **Help Center**
    - New and updated help guides from **#help-guide-requests**
  </Accordion>

  <Accordion title="How We Prioritize" icon="arrow-up-wide-short" iconType="duotone">
    | Priority | Task types |
    | --- | --- |
    | **High** | Service-impacting or critical tasks (these come first, even before onboarding), Active Unit Adjustment requests, and onboarding requests |
    | **Medium** | Account updates and data migration projects. Work these by due date, then by ticket age. |
    | **Daily** | Partner service provider requests, owner requests, and failed work order syncs |

    <Note>
      Medium-priority work yields to high-priority tasks, returned tasks, and the CPT Optional Benefits deadlines in the first weeks of the month.
    </Note>
  </Accordion>
