**What it means:** the Propertyware ID Latchel has for the property (the **ref property ID** / **ref unit ID**) is no longer valid in Propertyware, so work orders for that property can't sync. This usually happens when the PM deleted and recreated the building, or moved the property/building to a different portfolio in Propertyware. The ref IDs in Latchel need to be realigned with Propertyware.

<Info>
  Propertyware rejections now show up on the [Integration Health dashboard](https://app.latchel.com/admin/integration-health) as **Outgoing work orders** / **Stuck work orders** failures, with the Propertyware error on each work order. DS monitors the dashboard, so check whether DS is already working on the PM before you start. See [Job Aid: Integration Functionality, Troubleshooting, and Setup Steps](/latchel-admin/Product-Support-Team/Job-Aid-Integration-Functionality-Troubleshooting-and-Setup-Steps).
</Info>

### Reconciliation Steps

1. **Check Integration Health.** Open the PM's row and read the error on the affected work order(s). If the problem is tagged **Escalated to engineering**, or DS is already on it (check `#data-support-requests` and `#integration-health`), add your ticket context to that thread instead of starting a new one.
2. **Get the correct Propertyware IDs yourself if you can.**

   - Check the [software login spreadsheet](https://docs.google.com/spreadsheets/d/16B1d5acwDRvx6w8BkSuL4_QAOZmcXKYwf5HFpMcwRdU/edit?gid=2017091315#gid=2017091315) (confidential) for the PM's Propertyware credentials.
   - **If we have them:** log in to Propertyware, open the property, and copy the **Property ID** from the URL (see the example below). You can also export a property report that includes the ref IDs (walkthrough in section 4.4 of the job aid).
   - **If we don't:** ask the PM for screenshots using the template below.
3. **Compare against Latchel.** Open the property in the Latchel console (or pull the Integrations tab property report / P1 query) and compare its **ref property ID** and **ref unit ID** to what's in Propertyware.

   - Before changing anything, check for a **disabled or duplicate** property in Latchel that already has the correct Propertyware ID. If one exists, follow the duplicate steps in section 4.1 of the job aid instead.
   - The integration property report may not include every property (e.g., a PM with 1,000+ properties whose report only showed 63). If it's incomplete, use the PM's Propertyware export instead.
4. **Request the fix.** Post in `#data-support-requests` with the Latchel property link, the ID currently in Latchel, the correct Propertyware ID, and the screenshot/export. DS updates the ref ID.
5. **Re-send the work order** once the ref ID is fixed: open the work order and press **Sync Now** on its integration banner (or re-send from the failed-sync list). Confirm it reached Propertyware.
6. **Still failing** with matching ref IDs and a current sync? Submit a [bug report](https://app.latchel.com/admin/bug-reports) with the screenshots and what you checked, or use **Escalate to engineering** on Integration Health if that's the recommended action.

**Real example:** a work order showed as synced, but the PM couldn't find it in Propertyware. In Propertyware the property had Ref Property `19016125172` and Ref Unit `2008088596`, but in Latchel both the property ID and ref property ID were `2008088596`. There was no disabled or duplicate property with the correct ID, so the ref property ID in Latchel was updated.

### Suggested Template (if we don't have the PM's Propertyware login)

Hi [PM Name],

Thank you for bringing this to our attention. After reviewing the error, we found that the Propertyware ID associated with [property address] no longer exists in Propertyware. This can happen when a property or building is deleted and recreated, or moved to a different portfolio.

To realign the data, could you please send us:

- A screenshot of the full property page in Propertyware, with the URL clearly visible.
- If the property is assigned to a portfolio, a screenshot of the portfolio screen with the URL clearly visible, including the portfolio name.

Once we have these, we'll update the data on our end so your work orders sync correctly.

Thank you!

### Related Propertyware Errors

| Error | What it means | What to do |
| --- | --- | --- |
| **"Location is invalid"** | Propertyware doesn't recognize the property the work order points to (often a duplicate or recreated property). | Check for duplicates in Latchel and compare ref IDs as above. If the setup is wrong in Propertyware, the PM fixes it there. Then re-send the work order. |
| **"Unit ID is invalid"** | The unit may no longer exist, or is inactive, in Propertyware. | Confirm the unit's status with the PM or in Propertyware. The PM fixes the unit on their side, or DS updates the ref unit ID. Then re-send. |
| **"Propertyware created work order … do not re-send"** | The work order already exists in Propertyware; only the link back to Latchel failed. | **Do not re-send** (it will create a duplicate). Escalate to engineering to link it. |
| Work order request "missing integration data" / missing reference ID | The Latchel property is missing its ref ID (e.g., no ref unit ID) even though it's in the PM's property report. | Compare against the integration report and request the ref ID update in `#data-support-requests`, then retry the work order. |
