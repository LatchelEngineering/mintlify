<Note>
  **Objective:** This guide helps Product Support pick the right AI tool for the job, use it well, and keep our own judgment in the answer.

  **Rule of thumb:** AI tools are inputs, not the final product. Latchel policies and the facts you can see on the ticket, work order and account override what an AI tool says.
</Note>

<Warning>
  **A quick reminder:** the Minion is a great tool, but it can sometimes get things wrong. This goes for every AI tool. If an answer doesn't seem right, or it doesn't match what our engineers or product team have told us, check with one of them before taking the tool's word for it.
</Warning>

### **Which tool for which job**

| If you need to... | Use | Where |
| :-- | :-- | :-- |
| Find out what Latchel's SOPs, policies, job aids or help guides say to do | **Mintlify Assistant** | Tag it in Slack, or use the Help Center |
| Find out what happened on a work order, invoice, property, vendor or company | **Minion** | [#ask-the-minion](https://latchel.slack.com/archives/C0C9GE19KFH) |
| Find out how the system behaves in a situation (dispatch, billing, messaging, integrations), or whether something is a bug or working as designed | **Minion** | [#ask-the-minion](https://latchel.slack.com/archives/C0C9GE19KFH) |
| Get a count, trend or export of records for one company or question | **Minion** | [#ask-the-minion](https://latchel.slack.com/archives/C0C9GE19KFH) |
| Read, summarize or draft from ticket threads, Slack threads, docs and sheets, or pull from several of our tools at once | **Claude with connectors** | Claude |
| Count, trend or compare across many records | **BigQuery, through Claude** | Claude |
| Investigate a Deep Dive (Standard DD or Invoice Dispute DD) | **DD Agent** | The Deep Dives project in Claude |
| Make a policy call (should we take the job, what is the customer owed, how to handle an exception) | **A person: Ops, your PSM or the CSM** | N/A |
| Diagnose slow pages or timeouts | **An engineer** | N/A |
| Sort out an AI answer that looks wrong or conflicts with what engineering or product told you | **An engineer or the product team** | N/A |

### **Mintlify Assistant**

| | |
| :-- | :-- |
| **When** | You need an SOP, policy or guidance answer: which SOP applies, what a job aid says, how a feature is explained to customers |
| **For what** | Finding the right SOP, job aid or help guide, and a plain-language summary of it |
| **How** | Tag the Mintlify Assistant in a Slack message and ask the question the way you'd ask a teammate, then open the page it cites and read it yourself. Use the Help Center link, not a legacy Confluence one |
| **Why** | The Help Center is our source of truth. Confluence is legacy and out of date |

<Warning>
  **Don't tag the Minion for SOP, policy or guidance questions.** The Minion has no access to our SOPs or policies. Tag the Mintlify Assistant instead.
</Warning>

### **The Minion**

| | |
| :-- | :-- |
| **When** | The ticket, the work order and the SOPs don't tell you what the system did or what the customer saw |
| **For what** | What happened on a specific record, how the product behaves, integrations, counts, and CSV exports of records |
| **How** | Mention the Minion in [#ask-the-minion](https://latchel.slack.com/archives/C0C9GE19KFH) with a work order number, a name and roughly when it happened. One question per thread. Details below |
| **Why** | It reads Latchel's code and a copy of the production database, so it can answer "what does the system do?" faster than digging yourself. It can't answer "what should we do?" |

**Rule of thumb:** If the question is "what does the system do?", ask the Minion. If it's "what should we do?", ask a person.

#### What is the Minion?

A read-only assistant for Latchel's systems. It looks things up and explains them in plain terms. It can't change anything.

#### What can it access?

| It can see | It can't see |
| :-- | :-- |
| Latchel's code: the main app, the integrations service and the package they share. Read-only, refreshed every few minutes | Server logs and monitoring dashboards |
| A read-only copy of the production database. It runs a few seconds behind live and covers work orders, invoices, properties, vendors, tenants, companies and more | SOPs and internal docs |
|  | Slack history outside its thread |
|  | Email and Wavelength tickets |
|  | The property management platforms themselves |

#### What can it answer or investigate?

| Type of question | Example |
| :-- | :-- |
| **What happened on a specific record** | When a vendor was assigned or removed, why a work order is in its current status, or what was billed |
| **How the product works** | How dispatch, billing or messaging behaves, or which fields and options exist |
| **Integrations** | How Latchel syncs with RentManager, Rentvine, Propertyware, Buildium, Yardi and Leo, and what data moves between them |
| **Counts and trends** | How many work orders a company opened last month |
| **Reports and exports** | It can pull a query result and attach it to the thread as a CSV file |
| **Whether something is a bug** | It can say whether something looks like it's working as designed |

#### What can't it do?

| It can't | Who to ask instead |
| :-- | :-- |
| **Make changes of any kind.** It can't edit records, reassign vendors, send messages, fix data or deploy code | You, or the team that owns the change |
| **Diagnose performance problems** like slow pages or timeouts | An engineer |
| **Make business policy calls.** Whether to take a job, how to handle an exception, or what a customer or vendor is owed | Ops or the CSM |
| **Share credentials or security details** | N/A |
| **Troubleshoot code or write fixes.** It can tell you what happened and whether it looks like a bug | Engineering |
| **Check or "counter-check" a Deep Dive, or the output of Claude or the DD Agent.** That isn't what the Minion is for, and it can't open the Google Doc or Wavelength ticket anyway | You. Validate the Deep Dive yourself against the ticket, the work order and the instructions as written. See [The DD Agent](#the-dd-agent) |

#### Can it tell me how a process works?

Yes, if it's how the _system_ runs it. It can tell you what happens to a work order when a tenant cancels, when a vendor is notified, how a job moves through its statuses, or when an invoice is sent. That comes from the code and the data.

It can't tell you how a _person_ should handle a situation, who to escalate to, or what steps to follow. It has no access to SOPs, policies or team workflows. Tag the Mintlify Assistant in Slack, or use the Help Center, for those. Don't ask the Minion for SOP, policy or guidance answers.

#### How do I get a good answer?

- Be specific. A work order number, invoice number, or company or property name helps a lot.
- Mention the Minion in your message, and ask one question per thread.
- It can't open Wavelength or Google Docs links. Paste the customer's email text or the details into the thread.
- Say roughly when it happened.
- Number your sub-questions and name the identifiers (work order, invoice, company, property) for each one.
- Say what you want back: a yes or no, a timeline, a list, or a CSV.
- Ask it to flag anything it couldn't find instead of guessing. For example: "If you can't find it, say so rather than filling in the gap."
- To check a customer's claim (for example, "I emailed you on Tuesday"), give it the claim and the date range and ask it to find the exact record or message that matches, or say none exists.

#### What are some questions that work well?

| Goal | Example question |
| :-- | :-- |
| Why something happened | "Why was the vendor removed from work order 123456 yesterday?" |
| History | "What's the history of status changes on work order 123456?" |
| An invoice | "Did invoice 7890 get sent to the PM, and what was on it?" |
| System behavior | "When a tenant cancels a work order, does the vendor get notified?" |
| Integrations | "Does a work order from Rentvine sync back when it's completed?" |
| Counts | "How many emergency work orders did [company] have in October?" |
| Exports | "Can you export all open work orders for [company] older than 30 days as a CSV?" |
| Account settings | "Is AI messaging on for [company], and are automated vendor calls on?" |
| Finding an example of a complaint | "A PM says the AI messaged a tenant after they asked it to stop. Can you find the conversation on work order 123456 and show what was sent and when?" |
| Several questions at once | "For work orders 123456 and 123457: 1) who was assigned, 2) when did the status change to Scheduled, 3) was anything sent to the tenant? Flag anything you couldn't find." |

#### What are some signs the answer is incomplete or wrong?

| If the Minion... | Do this |
| :-- | :-- |
| Says it couldn't open a link, reach Freshdesk or Wavelength, or see a source | Paste the text into the thread and ask again |
| Says a search "could have missed" something because the wording was different | Try other keywords, or check the record yourself |
| Gives a different answer when you ask a second way, or conflicts with what you see on the work order | Don't pick one. Ask in the thread what it based each on |
| Assumes how a team runs things (for example, which on-call rotation or process is in use). It reads the code and data, not how our teams work day to day | Check with a person |
| Answers a policy, scope or "what should we do" question (for example, whether a repair is in a PM's maintenance scope) | That belongs to Ops, your PSM or the CSM |

#### What if it can't find anything, or the lookup times out?

A lookup can time out. Try again with a narrower question or a specific work order number. If it still finds nothing, write "Minion found no example" in your ticket note or escalation. That is useful to the CSM and better than leaving it blank.

#### Can I rely on its answer?

Not without checking. The Minion is a great tool, but it can sometimes get things wrong. Treat it as research, like the Mintlify Assistant. Check what it returns against the work order and the account, and use your own judgment.

If an answer doesn't seem right, or it doesn't match what our engineers or product team have told us, check with one of them before taking the Minion's word for it. If you escalate or ask the PSM for help, say what you verified yourself. Don't send its answer to a customer as the answer.

#### Where do I keep the answer?

Paste the Minion thread link into the ticket as an internal note.

#### What do I do with what it finds?

| If the Minion's answer shows... | Do this |
| :-- | :-- |
| **A bug** | Mention the Minion with "bug" and a short description. The Minion files the bug report. |
| **Ops agent feedback** | The Minion doesn't file this. Use the **Agent Feedback** workflow in `#svc-ops-feedback`. See [Job Aid: Slack Channels & Escalation Workflows](/latchel-admin/Product-Support-Team/Job-Aid-Slack-Channels-Escalation-Workflows). |
| **A feature request** | The Minion doesn't file this. Use the **Feature Request** workflow in `#feature-requests`. See [How to Handle: Feature Requests](/latchel-admin/Product-Support-Team/How-to-Handle-Feature-Requests). |
| **A situation that needs the CSM** (for example, an account-level request to turn off AI) | Escalate with [SOP: Escalating Tickets to the CSM](/latchel-admin/Product-Support-Team/SOP-Escalating-Tickets-to-the-CSM). |

### **Claude with connectors**

| | |
| :-- | :-- |
| **When** | The work involves reading, summarizing, comparing or drafting, or you'd otherwise copy things between tools by hand |
| **For what** | Summarizing a long ticket or Slack thread, pulling context from Wavelength, Slack, HubSpot, Google Drive or Sheets and Mintlify in one place, drafting an escalation summary or a first reply for you to edit, and organizing notes or sheets |
| **How** | Tell Claude the goal, which ticket or record to look at, and what you want back. Ask it to say what it couldn't find instead of guessing. Check every fact, number and link it gives you against the source before using it |
| **Why** | It saves time on the reading and drafting. You still own the recommendation and the final message |

<Info>
  The connectors you can use depend on how Claude is set up for you. If a connector you need is missing, ask your PSM.
</Info>

### **BigQuery, through Claude**

| | |
| :-- | :-- |
| **When** | The question is about many records: trends over time, counts by company, comparisons, or data for the WBR or a Deep Dive |
| **For what** | Counts, trends, comparisons and exports that are too big or too wide to ask the Minion for a single record |
| **How** | Tell Claude the question, the date range and the companies or segments. Ask it to show the query it ran and how it defined each number. Spot-check a few rows against the work orders yourself |
| **Why** | One question across thousands of records is faster in BigQuery than looking at records one at a time |

<Tip>
  **Minion or BigQuery?** One work order, invoice or company and a "what happened?" question: ask the Minion. A trend or comparison across many records: use BigQuery through Claude. Either way, check a sample before you share a number.
</Tip>

### **The DD Agent**

| | |
| :-- | :-- |
| **When** | A Standard DD or Invoice Dispute DD comes in from `#ps-dd-sddi` |
| **For what** | The research and first drafts of the Deep Dive. A PS team member checks the facts, makes the calls and sends the final customer email |
| **How** | Follow [SOP: Running a Deep Dive with the DD Agent (PILOT)](/latchel-admin/Product-Support-Team/sop-running-a-deep-dive-with-the-dd-agent-pilot). Start with the [kickoff prompt](/latchel-admin/Product-Support-Team/Job-Aid-DD-Agent-Kickoff-Prompt) and answer every question the agent asks |
| **Why** | It does the evidence gathering consistently so people can spend their time on validation and judgment |

<Warning>
  **The DD Agent can be overly deferential about policies it doesn't understand.** It can also read an instruction that was followed as written as a mistake we made. For example, if a property's instructions say to call the owner first for emergencies, the agent may treat calling the owner first as an error instead of the instruction we were given. It is a statistical model that is good at producing plausible language, and plausible isn't the same as right. Check what it says about any policy or instruction against the instruction itself (the property's pre-dispatch instructions, the account settings, the SOP), and make the call yourself.

  **Don't ask the Minion to counter-check a Deep Dive.** Validation is done by a PS team member, as the [Validation section of the DD SOP](/latchel-admin/Product-Support-Team/sop-running-a-deep-dive-with-the-dd-agent-pilot#validation) describes.
</Warning>

### **Rules for every AI tool**

| Rule | What it looks like |
| :-- | :-- |
| **Your judgment is the answer** | Say what you think the right path is and why. A summary of what the tool found is not a recommendation |
| **Verify before you rely on it** | Check the answer against the ticket, the work order, the account and the SOP. Policies and visible facts win over AI output |
| **Verify every link** | Open each link before you send it. Never send a customer a legacy Confluence link |
| **Show your checking** | When you escalate or ask the PSM for help, say which tool you used, what it said and what you verified yourself |
| **Don't forward AI output as the answer** | Write the customer reply yourself, using the tool's output as input |
| **Plausible isn't the same as right** | AI tools can sound confident and still be wrong, and they tend to go along with what's in front of them. If an answer explains away an instruction or policy as a mistake, read the instruction yourself before you agree |
| **Use the tool for its own job** | Don't use one AI tool to check another's work. Use the Minion for what the system did, the Mintlify Assistant for SOPs and policy, and your own validation for Deep Dives |
| **When it doesn't match** | If the answer conflicts with what engineers or product told you, ask them before using it |
