We now classify every ticket using three fields — **Category**, **Attributes**, and **Tags** — instead of a single tag list. Each field answers a different question about the interaction, and together they give a complete picture: how it reached us, what it was about, and what it drove.

## How the Three Fields Work Together

| Field | Question It Answers | Selection | Required? |
| --- | --- | --- | --- |
| **Category** | How did this ticket reach us? | Single-select | Always |
| **Attributes — Topic** | What was the ticket about? | Multi-select | Always |
| **Attributes — Root Cause\*** | Why did it happen? | Multi-select | If applicable\* |
| **Tags** | What did this interaction drive or produce? What was the outcome? | Multi-select | Apply as many as apply |

A typical ticket gets tagged in this order:

1. **Category** — pick the one value that describes how the ticket arrived (a PM texted in, an SP called, an automation flagged it, and so on).
2. **Attributes — Topic** — pick every Attribute/Value pair that describes what the ticket was actually about (WO Coordination, Invoicing & Payments, Appfolio, and so on).
3. **_Attributes — Root Cause\*_** — if something went wrong, pick the one value that explains why (SP Performance, Platform Defect, PM Action or Delay, and so on). _Skip this if nothing went wrong — a routine question doesn't need a Root Cause._ **_Attributes — Root Cause\*_** — if something went wrong, pick every value that explains why (SP Performance, Platform Defect, PM Action or Delay, and so on). _Skip this if nothing went wrong — a routine question doesn't need a Root Cause._
4. **Tags** — select every outcome tag that applies (Resolved by PS, Bug Filed, CSM Handoff, and so on).

Tags describe the outcome — what the interaction produced, not what it was about. They're multi-select and independent of Attributes: apply every tag below that fits, even if that means several tags on one ticket.
