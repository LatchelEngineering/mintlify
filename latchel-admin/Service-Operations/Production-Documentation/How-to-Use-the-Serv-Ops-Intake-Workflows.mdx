## What This Process Is Trying to Solve

<Note>
  We want to prevent missed, lost, or delayed escalations and requests by providing a standardized workflow for submitting all Service Operations requests to the Product team. The goal is to ensure every bug, feature request, SOP update, or help article request is submitted through the correct Slack channel and form—creating an official audit trail, reducing channel clutter, and allowing Product and Ops to track, prioritize, and resolve issues efficiently.
</Note>

### Main Audience

Anyone in Latchel Ops escalating an issue or requesting a feature, design, or process/policy change.

### Bug Report, Latchel Minion, or High-Tech-Sev?

<AccordionGroup>
  <Accordion title="1. Ops Associate bug reporting">
    - **You know what should happen, but it isn't happening:** Submit a bug report directly through the [bug report form](https://app.latchel.com/admin/bug-reports).
    - **Something doesn't seem normal, but you're not certain it's a bug:** Post it in `#ops_assistance_hub` for Ops Support to validate. Include the WO link, what you expected, and what happened instead.
  </Accordion>

  <Accordion title="2. Ops Support validation and handling">
    Review the reported issue and determine whether it's a bug.

    - **You're certain about the expected behavior and can confirm it isn't working as expected:** Instruct the associate to submit a bug report through the [bug report form](https://app.latchel.com/admin/bug-reports).
    - **You're unsure whether it's a bug or need further validation:** Post the issue in `#ask-the-minion`.
    - **Your Minion thread confirms something isn't working as expected:** File the bug report directly using that thread. The associate doesn't need to submit a separate report when the issue has already been investigated and validated.

    <Warning>
      The Minion is a great tool, but it can sometimes get things wrong. If an answer doesn't seem right, or it doesn't match what our engineers or product team have told us, check with one of them before taking the Minion's word for it.
    </Warning>
  </Accordion>

  <Accordion title="3. Outages and critical issues">
    For app outages or issues preventing associates from performing their job duties, Ops Support escalates directly to Engineering through `#tech-high-sev-escalations`. Associates should flag these in `#ops_assistance_hub` right away.

    <Note>
      The Latchel Minion isn't equipped for this type of escalation. Don't ask it to investigate outages, system-wide latency, or connectivity issues with the Latchel Console. Go straight to `#tech-high-sev-escalations`.
    </Note>
  </Accordion>

  <Accordion title="Quick reference: where each issue goes">
    | Situation | Where it goes | Who submits |
    | --- | --- | --- |
    | **You know it's a bug.** You know what should happen, and it isn't happening. | [Bug report form](https://app.latchel.com/admin/bug-reports) → `#bug-report` | Associate, directly |
    | **Something doesn't seem normal, but you're not certain it's a bug.** | `#ops_assistance_hub` (Ops Support validates) | Associate |
    | **Ops Support confirms it's a bug.** | [Bug report form](https://app.latchel.com/admin/bug-reports) → `#bug-report` | Associate, when instructed by Ops Support |
    | **Ops Support is unsure or needs further validation.** | `#ask-the-minion` | Ops Support only |
    | **A Minion investigation confirms it's a bug.** | Bug report filed from the Minion thread | Ops Support |
    | **The app is down or you can't perform your job.** | `#tech-high-sev-escalations` (Engineering) | Ops Support only. Associates flag it in `#ops_assistance_hub`. |
  </Accordion>

  <Accordion title="Latchel Minion: what it can and can't do">
    The Latchel Minion is a read-only assistant for Latchel's systems. It looks things up and explains them in plain terms. It can't change anything.

    <Tip>
      If the question is "what does the system do?", ask the Minion. If it's "what should we do?", ask a person.
    </Tip>

    **What it can answer or investigate**

    - **What happened on a specific record:** a work order, invoice, property, vendor, or company. For example, when a vendor was assigned or unassigned, why a job is in its current status, or what was billed.
    - **How the product works:** what the system does in a given situation, such as how dispatch, billing, or messaging behaves, or which fields and options exist.
    - **Processes as the system runs them:** what happens to a work order when a tenant cancels, when a vendor gets notified, how a job moves through its statuses, or when an invoice is sent.
    - **PMS integrations:** how Latchel syncs with RentManager, Rentvine, Propertyware, Buildium, Yardi, and Leo, and what data moves between them.
    - **Counts and trends:** for example, how many work orders a company opened last month, or how many jobs are in a given status.
    - **Reports and exports:** it can pull a query result and attach it to the thread as a CSV file.
    - **Is this a bug?** It can say whether something looks like it's working as designed. If it looks broken, mention the Minion with "bug" and a short description to file it for Engineering.

    **What it can access**

    - The Latchel code (main app, integrations service, and the shared package between them), read-only and refreshed every few minutes.
    - A read-only copy of the production database, a few seconds behind live. It covers work orders, invoices, properties, vendors, tenants, companies, and more.
    - **Not available:** server logs, monitoring dashboards, SOPs or internal docs, Slack history outside the thread, email, or the PM platforms themselves.

    **What it can't help with**

    - **Making changes of any kind:** editing records, reassigning vendors, sending messages, fixing data, or deploying code.
    - **Performance problems** like slow pages, latency, or timeouts. It doesn't have monitoring access, so ask an engineer.
    - **Internal SOPs and team workflows:** how Ops should handle a situation, who to escalate to, or what steps to follow.
    - **Business policy calls:** whether we take a job, how to handle an exception, or what a customer or vendor is owed. Ask Ops or the account manager.
    - **Credentials or security details:** passwords, API keys, or how to exploit a weakness.
    - **Code-level troubleshooting or writing fixes:** that goes to Engineering, though the Minion can tell you what happened and whether it looks like a bug.

    **Example questions that work well**

    - "Why was the vendor removed from work order 123456 yesterday?"
    - "What's the history of status changes on work order 123456?"
    - "Did invoice 7890 get sent to the PM, and what was on it?"
    - "When a tenant cancels a work order, does the vendor get notified?"
    - "Does a work order from Rentvine sync back when it's completed?"
    - "How many emergency work orders did Acme Property Management have in October?"
    - "Can you export all open work orders for company X older than 30 days as a CSV?"

    The more specific you are, the faster it finds the answer. A work order number, invoice number, or company or property name helps a lot.
  </Accordion>
</AccordionGroup>

<Note>
  **The Latchel Minion is not a replacement for bug reports.** Ops Support uses it to validate an issue when it's unclear whether it's a bug.

  **It's also not the same as the Mintlify assistant.** The Minion answers questions about Latchel's systems: code, data, and how the product behaves. For SOPs and internal Service Ops processes, use the Mintlify assistant instead.
</Note>

### Types of Escalations & Requests

First, determine what kind of request you would like to escalate to the team. Use Table 1 below to figure out the type. If you’re still unsure if something is an issue or a change request, please discuss it with your colleagues or manager.

Table 1: Different Types of Requests

| Escalation or Request Type | Definition | Examples |
| --- | --- | --- |
| Bug Report | Escalation for when you're expecting X and X isn't happening.<br /><br />**Associates:** If you know what should happen and it isn't happening, submit a bug report directly. If you're unsure, post it in `#ops_assistance_hub` for Ops Support to validate first. Submit bug reports using this link: [<u>https://app.latchel.com/admin/bug-reports</u>](https://app.latchel.com/admin/bug-reports) (also pinned at the top of the `#bug-report` channel). | <ul><li>WO not behaving as it should. <ul><li>WOs stuck in Intake processing for more than 3 minutes.</li></ul></li><li>Notification sending under incorrect circumstances.</li><li>Call not being recorded.</li><li>Certain work orders not appearing on the user dashboard as expected.</li><li>Tasks created even if it shouldn’t</li></ul> |
| Feature Request | Request to add or change something in the Latchel console that will improve the user’s experience. Please note that these requests should be for things that don’t block any standard work or processes. Submit a feature request using this link: [app.latchel.com/admin/feature-requests](http://app.latchel.com/admin/feature-requests) (also pinned at the top of the #bug-report channel). | <ul><li>Request to add a vendor call history page</li><li>Remove task from the overall task list if someone has claimed it or is working on it</li></ul> |
| SOP Update Request | Request to change something in any current SOPs. These do not involve any changes in Tech. | <ul><li>Would be helpful to add a standardized template for speaking to an owner</li><li>Request to have all associates answer webchats</li><li>Consolidation request for a specific Slack channel</li></ul> |
| Public Latchel Help Article Request | Request to update or create a Public Help article in [https://help.latchel.com/s/](https://help.latchel.com/s/) for our customers to reference. | <ul><li>Create a page to show PMs how to use the LCN network.</li><li>Create a page to show Residents how to report issues with WOs.</li><li>Update a SP help article to correct X error in page.</li></ul> |
| Escalate to Sales | Request about New Property Manager Leads / Sales-related questions | <ul><li>Property Manager/Owner interested in Latchel services</li><li>Property Manager/Owner  asking for pricing</li><li>Any indication of a new Property Manager/Owner prospect in Latchel services</li></ul> |
| Diagnostic Flow Issues | Requests related to confusion, redundancy, or errors encountered within the diagnostic prompts during work order creation. | <ul><li>Duplicate or Conflicting Response Options in Diagnostic Prompts <ul><li>Redundant Answer Choices in Diagnostic Flow</li><li>Repetitive Responses for Same Issue Path</li></ul></li><li>Inconsistent Option Mapping During WO Creation</li></ul> |

### How to Submit Escalations & Requests

Once you’ve determined which Slack channel to submit your escalation or request to using the table above, you’ll then formally submit the actual request. Here are the general steps of how it works directly below.

**<u>STEP 1</u>**<u>:</u> Press the shortcuts button (lightning bolt at the bottom of Slack channel) to find the form to submit your escalation or request (see orange arrow in the screenshot below).

**<u>STEP 2</u>**<u>:</u> Then, identify which form is appropriate for your request. Please reference Table 3 below for what forms are available in each escalation/request Slack channel. Appendices A-B include the questions from each form.

_Important Note: **If an issue or request is not submitted through one of these forms in the following Slack channels, there is a risk that the product team misses the request.**_

Table 3: Forms in Each Escalation/Request Slack Channel

| Slack Channel | Form | How Form is Used |
| --- | --- | --- |
| bug-report | [https://app.latchel.com/admin/bug-reports](https://app.latchel.com/admin/bug-reports) | Use this form when you know what should happen and it isn't happening. If you're unsure whether it's a bug, post it in `#ops_assistance_hub` for Ops Support to validate first. If the app is down or you can't perform your job, Ops Support escalates to Engineering through `#tech-high-sev-escalations` instead. |
| ops-requests | [app.latchel.com/admin/feature-requests](http://app.latchel.com/admin/feature-requests) | This form is used for any non-issue submissions, which are feature, design or diagnostic workflow requests. |
| ops-requests | SOP Update Request | This form is used for any process/policy change requests or suggestions. |
| ops-requests | Public Latchel Help Article Request | This form is used to request updates to our public Help Center library ([https://help.latchel.com/](https://help.latchel.com/s/). |
| ops-requests | PS SOP Needs Update | This shouldn’t be used by non-Product Support team members. |

<Note>
  If you reported a bug, but the issue hasn’t been fixed and you’re blocked from executing your duties, make sure to keep the Operations Support Specialist team in the loop.
</Note>
