## 🧠 What This Process Is Trying to Solve

<Note>
  We want to prevent missed, delayed, duplicated, or inconsistent replies when associates handle customer messages. This job aid gives a short list of what to do, and what to avoid, so every customer gets a prompt, accurate, and professional response.
</Note>

**🎓Training Content**

<Note>
  The contents of this page have been included in the **SMS & Webchat Cross-Training Coassemble course.**
</Note>

<Info>
  **🔔 Where messages live**

  - **Conversations icon:** text messages from residents, service providers (SPs), Property Managers and Owners. Latchel AI answers resident and SP messages where it is active and hands off to staff when needed. Follow [Job Aid: Handling AI Messaging - Conversations](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Handling-Resident-and-SP-Conversations-AI-Messaging-Beta), including [What a Latchel AI Handoff Looks Like](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Handling-Resident-and-SP-Conversations-AI-Messaging-Beta#what-a-latchel-ai-handoff-looks-like).
  - **Legacy SMS icon:** PM web chats only. Follow [How to: Use Text Message (SMS/Webchat) Functions (in Latchel Console)](/latchel-admin/Service-Operations/Production-Documentation/How-to-Use-Text-Message-SMS-Webchat-Functions-In-Latchel-Console).
  - For both, research and answer the request using [How to: Handle Conversations/Webchat](/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-SMS-Webchat-Contacts-New-Support-Framework).
</Info>

Associates working the messaging queue have 3 goals:

1. Reply promptly. Work the oldest unhandled message first (see the response-time note below).
2. Provide a great experience.
3. Solve the customer's issue or answer their question.

<Warning>
  **⏱️ Response time**

  In Conversations, a resident or SP message that goes **10 minutes** without a staff reply is highlighted in red in **Team** so anyone can pick it up ([Job Aid: Handling AI Messaging - Conversations](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Handling-Resident-and-SP-Conversations-AI-Messaging-Beta)). This is an aging flag, not a reply target: don't wait for it.

  The associate reply-time target for Conversations and PM web chat is **pending SME confirmation**. Ask Ops Support if you are unsure.
</Warning>

## ✅ Picking up and claiming messages

| Do | Don't |
| --- | --- |
| Work the **oldest** unhandled message first by timestamp, across **Conversations → Team** and the legacy SMS icon. Both have equal priority. | Don't pick newer or easier-looking threads, or treat Conversations as lower priority than SMS. |
| In Conversations, check for _"[name] is typing…"_, then click **Mark as Handled** before you reply. | Don't jump into a thread where someone is typing, or assume opening a thread claims it. |
| If a Conversations message needs no reply (e.g., "Thank you"), just click **Mark as Handled**. | Don't send an extra message; clicking **Mark as Handled** is all you need. |
| For PM web chat, assign and close the chat per [How to: Use Text Message (SMS/Webchat) Functions](/latchel-admin/Service-Operations/Production-Documentation/How-to-Use-Text-Message-SMS-Webchat-Functions-In-Latchel-Console). | Don't look for Assign or End Conversation in Conversations. There is no assigning, ending, or closing step there. |
| Before acting on a work order, check the top of the WO for other people viewing it. If the request will take you more than 10 minutes, reach out to them first. | Don't assume you're the only one working the WO. |

<Note>
  **Why:** Working the oldest message first keeps wait times down. Claiming with **Mark as Handled** and checking for typing or other WO viewers stops two associates from working the same request.
</Note>

## 💬 Replying

| Do | Don't |
| --- | --- |
| Read the whole thread (Latchel AI, associate, and customer messages) and confirm the tagged WO. Only ask for what's genuinely missing. | Don't make the customer repeat what they already told Latchel AI or a teammate. |
| Reply with the answer or next step right away. Latchel AI already told the customer they're being passed to a person. | Don't send a separate acknowledgment-only message in Conversations. |
| Keep messages short and to the point, but kind, and say "please" and "thank you". Follow [Job-Aid: Guide to write SMS/Webchat or email to customers](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Guide-to-write-SMS-Webchat-or-email-to-customers). | Don't take shortcuts that sacrifice the customer experience. Follow the [Customer Service Tenets](/latchel-admin/Service-Operations/Latchel-Library/Informational-Latchel-Customer-Service-Tenets-High-5-Your-Customers-Today) and [Customer Experience Review guidelines](/latchel-admin/Service-Operations/Quality-Program/Job-Aid-Customer-Experience-Review-Calibration-Guidelines). |
| On outbound messages, say which WO and issue you're writing about and why. | Don't send an outbound message without the related WO or issue for reference. |
| If you need time to research, tell the customer you'll take a moment, per [How to: Handle Conversations/Webchat](/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-SMS-Webchat-Contacts-New-Support-Framework). | Don't leave the customer without an update while you research. |
| Hand the next reply to Latchel AI only in the cases listed in the FAQ [When can I switch Handled by to AI?](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Handling-Resident-and-SP-Conversations-AI-Messaging-Beta#when-can-i-switch-handled-by-to-ai) (e.g., requesting photos). | Don't switch to AI when you need the customer's answer to decide the next step, on emergencies (unless only waiting on photos), on time-sensitive items, or when coordinating with the PM. |
| Send the CSAT link at the end of the interaction **only to Property Managers**. | Don't send the CSAT link to residents, SPs, or owners, or to a PM when you're only requesting photos or the conversation is still open. |

## 🛠️ Resolving the request

| Do | Don't |
| --- | --- |
| Solve the issue or answer the question during the conversation. | Don't create tasks for other team members to avoid the work. If you must create one, follow [SOP: Work Order Follow-ups and Updates](/latchel-admin/Service-Operations/Production-Documentation/SOP-Work-Order-Follow-ups-and-Updates). |
| If an existing task covers the same request and is older than 2 days, take care of it and resolve it. | Don't leave an old task in the queue for the same request you're already handling. |
| If the issue will take more than 10 minutes, escalate to Operations Support Specialists for guidance. | Don't stay stuck on a long session without letting Ops Support know. |
| Contact PMs through the right channel: a **task for the PM** when we need an action or info from them; an **email from Assembly** to the property's PM user group when no reply is needed; a **call** (then voicemail and SMS) for emergency WOs within calling guidelines. | Don't call or contact the PM unnecessarily. |
| Stay within your assigned queue, per [Cross-Training & Queue Scope](/latchel-admin/Service-Operations/Production-Documentation/Informational-Basic-Service-Ops-Guidelines-and-Rules). | Don't take on another queue's work unless you're assigned Flex. |

## 🔒 Privacy and conduct

| Do | Don't |
| --- | --- |
| Share only what the requester can already see in their dashboard, per [Basic Service Ops Guidelines and Rules](/latchel-admin/Service-Operations/Production-Documentation/Informational-Basic-Service-Ops-Guidelines-and-Rules). | Never share a PM's or owner's private information (name, phone, email) unless explicitly authorized. Never give SP contact details to someone who isn't registered. |
| If Latchel AI shares private PM information, submit a bug report as described in the [Conversations job aid FAQ](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Handling-Resident-and-SP-Conversations-AI-Messaging-Beta). | Don't skip the bug report. |
| For hostile customers, follow [Job Aid: How to Deal with Hostile Customers](/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-How-to-Deal-with-Hostile-Customers). In Conversations, after the final script, click **Mark as Handled**, stop responding, and report it in #sms-squad. | Don't take it personally, and don't stop responding before giving both warnings. |
| If a customer brings up a different WO in the same thread, escalate to Operations Support Specialists. | Don't handle the other WO in that thread without escalating. |

## 📝 Documenting

| Do | Don't |
| --- | --- |
| Leave a WO note when the conversation led you to change the work order, following [How to: Write Effective Notes](/latchel-admin/Service-Operations/Production-Documentation/How-to-Write-Effective-Notes). | Don't copy the conversation into notes or tag it. History is saved in the WO **Conversations** tab. |

## 🇪🇸 Spanish messages received by non-Spanish-speaking associates

| Do | Don't |
| --- | --- |
| Respond immediately using the Spanish SMS Translator, starting with the disclosure message (see [How to: Handle Spanish SMS/Emails/Calls](/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Spanish-SMS-Emails-Calls)). | Don't wait for a Spanish-speaking teammate or Ops Support before responding. That step is no longer part of the process. |

## **🎯 When to Break This SOP**

**Do not break or deviate from this SOP on your own authority.** Always escalate to an Ops Support specialist or follow explicit instructions if you believe an exception is necessary.
