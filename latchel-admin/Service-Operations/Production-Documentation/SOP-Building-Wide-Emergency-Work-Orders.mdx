## 🧠 What This Process Is Trying to Solve

<Note>
  When one building-level problem (e.g., a shared boiler or HVAC system) affects **multiple units**, each resident may submit their own emergency work order. Handling each one separately leads to **duplicate dispatches, duplicate charges, repeated calls to the property team, and confusion for vendors**.

  The goal is to keep **one work order — the Main WO — as the single source of truth** for the incident, so the issue is troubleshot, escalated, and dispatched **once**, while every affected resident is still kept informed.
</Note>

## 📘 Key Terms

- **Incident:** Reports of the **same issue type**, from **different units in the same building**, happening around the **same time** (e.g., several "boiler down" reports in one evening).
- **Main WO:** The **one** work order for the incident that is troubleshot, escalated, dispatched, and updated.
- **Duplicate WO:** Every other work order from **another unit** for the same incident. Duplicate WOs are **never dispatched or escalated** and are **canceled** after the resident is informed.

<Note>
  📝 **Merging is not an option for building-wide duplicates.** The system only allows merging work orders under the **same property (unit)**. Units in the same building are separate properties, so building-wide duplicates are handled by **canceling them and referencing the Main WO**, as described in this SOP.
</Note>

## 📋 Step-by-Step Process

<Warning>
  **Use a different SOP if any of these apply:**

  - **911 situation** (fire, gas leak, carbon monoxide) → [How to: Handle 911-Severity Type Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-911-Severity-Type-Work-Orders) **first**.
  - **Utility outage** (no water, gas, or power from the utility company's side) → [(Emergency) How to: Handle a Utility Issue](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Emergency-How-to-Handle-a-Utility-Issue).
  - **Same issue reported more than once from the same unit** → [(⛑EMERGENCY) How to: Handle Duplicate Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/EMERGENCY-How-to-Handle-Duplicate-Work-Orders).
  - **Unit-specific issue** (e.g., a leak inside one unit, a unit's own heater or electrical panel) → [How to: Handle Emergency Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders).
  - **Non-emergency** per the PM's intake settings → see **FAQ Q2**.
</Warning>

### Step 1: Confirm This SOP Applies

Confirm **all three** before treating reports as one building-wide incident:

1. **Same building:** The reports come from the **same street address**, even if the unit numbers differ.
2. **Same issue:** The reports describe the **same type of problem** (e.g., boiler down, no heat) and point to the **building**, not to individual units.
3. **Shared system confirmed:** At least **one** of the following confirms the equipment serves multiple units:
   1. **Property / PM notes:** Property, critical, or pre-dispatch notes mention a **shared building system** (e.g., boiler, water heater, HVAC system, building-wide electrical panel).
   2. **Prior work orders:** Previous work orders reference a **single equipment tag or location** serving the building.
   3. **PM / EEC confirmation:** The Property Manager or an Emergency Escalation Contact confirms the system is shared.
   4. **Service Provider note:** A Service Provider's notes on a related WO confirm the system serves multiple units.

⚠️ **If you can't confirm all three:** do **not** consolidate. Handle each work order separately using [How to: Handle Emergency Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders), add a note on each WO listing the other related WO numbers, and escalate to the **Operations Support Specialists** via **#ops_assistance_hub** for guidance.

### Step 2: Search for Existing Work Orders in the Building

1. Copy the building's street address **without the unit number**.
2. Open the **Property Manager (PM) profile** and go to the **Maintenance** tab.
3. Paste the address into the search bar to display all work orders for units in that building.
4. Use what you find to decide your next step:

| What you find | What to do |
| --- | --- |
| A work order whose title starts with **"Main WO -"** | The Main WO already exists. Your work order is a **Duplicate WO** → go to **Step 4**. |
| Other active work orders for the same issue, but **no Main WO** yet | Set up the Main WO → go to **Step 3**. |
| **No other work orders** for this issue | Your work order becomes the Main WO → go to **Step 3**. Expect more reports. |

### Step 3: Set Up and Work the Main WO

1. **Choose the Main WO**
   1. Select the **earliest created active work order** for the incident.
   2. 📝 **NOTE:** If the earliest work order was already **canceled or completed**, skip it and select the earliest work order that is still **active**.
   3. 📝 **NOTE:** If a Service Provider has already been dispatched on a **different** work order for this incident, do not choose on your own — escalate to the **Operations Support Specialists** via **#ops_assistance_hub** first to avoid a double dispatch.
2. **Rename the Main WO**
   1. Format: **Main WO - (Issue)**
   2. Example: **Main WO - Boiler Down**
3. **Add a note to the Main WO** that includes:
   1. **Issue:** A 1-sentence summary of the problem.
   2. **Units Reporting:** A running list of affected units (e.g., Unit 101, Unit 203, Unit 305…).
   3. **Verification Method Used:** How you confirmed the shared system (property note, PM/EEC confirmed, prior WO, or Service Provider note).
4. **Post in #ops_info_center** so the team knows not to dispatch or escalate from other units' work orders. Reply in the **same thread** whenever new units report or the incident changes.

   1. 📝 _"Building-level emergency consolidation in progress: [Building Address] – [Issue]._<br />_Tracking under Main WO #[number]. Multiple units reporting. Please do not dispatch from additional unit WOs or call the escalation contacts again for this incident."_
5. **Work the Main WO as a standard emergency WO.** Troubleshoot, classify severity per the PM's intake settings, and escalate or dispatch following [How to: Handle Emergency Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders).

   1. Use the [Job Aid: Troubleshooter Question Bank](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Troubleshooter-Question-Bank) for troubleshooting guidance.
   2. If the issue is in a **common area** (e.g., a boiler room), follow the **common area** guidance in that SOP — call residents for **access information and clarification only**, not troubleshooting. See **FAQ Q4**.
6. **Dispatch and escalate from the Main WO only.**

   1. All Service Provider dispatches and EEC/PM calls for the incident happen on the **Main WO**.
7. **Keep every update on the Main WO.**

   1. Record all **Service Provider updates, approvals, EEC/PM calls, and status changes** on the Main WO.
   2. Link every call related to the incident to the Main WO. Refer to [How to: Link Calls to a WO](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Link-Calls-to-a-WO).

### Step 4: Handle Each Duplicate WO

Repeat this for **every work order** from **another unit** for the same incident:

1. **Do not dispatch** from the duplicate WO. ❌
2. **Do not call the Escalation Contacts again.** 📵
   1. If the EEC/PM was already contacted about this incident on the Main WO and there are **no new updates or changes**, do **not** call again. This follows the General Rule in the Key Reminders of [Job Aid: PM Outbound Communication for Emergency WOs](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-PM-Outbound-Communication-for-Emergency-WOs).
   2. Instead, **link the existing EEC call** to the duplicate WO and mention it in your note. Refer to [How to: Link Calls to a WO](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Link-Calls-to-a-WO).
   3. Only call again if the new report brings **new information** that changes the situation (e.g., the issue is now PD/EH) — see **FAQ Q1**.
3. **Contact the resident and set expectations**
   1. 🗨️ **Say something like (call or SMS):** _"Hello [Resident Name], your report has been consolidated as part of a building-wide issue and is being tracked under Main WO #[number]. To ensure a coordinated resolution, no separate dispatch will be made for your unit, and your duplicate request will be canceled. If anything changes or gets worse in your unit, please contact us right away. We appreciate your understanding."_
   2. 📝 **NOTE:** If you **cannot reach the resident**, do **not** cancel the WO yet. Follow the unresponsive-resident steps in [(⛑EMERGENCY) How to: Handle Duplicate Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/EMERGENCY-How-to-Handle-Duplicate-Work-Orders) and note that this WO appears to be part of Main WO #[number]. Still do not repeat EEC calls already made on the Main WO.
4. **Rename the duplicate WO**
   1. Add **"Duplicate"** at the beginning of the title (same as the single-unit duplicate process).
   2. Example: **Duplicate - Main WO #[number] - Boiler Down**
5. **Add a note to the duplicate WO** 📝 with the **Main WO number and link** 🔗.
   1. _"This appears to be the same building-level emergency affecting multiple units. This unit's report is being tracked under Main WO #[number] ([link]). No separate dispatch created."_
6. **Cancel the duplicate WO** via the **Take Action** button so it cannot be dispatched by mistake.
7. **Update the Main WO**
   1. Add the unit to the **"Units Reporting"** list.
   2. Add the **duplicate WO number** to the Main WO note.
   3. Reply in the **#ops_info_center** thread with the new unit.

### ✅ Quick Reference: Main WO vs. Duplicate WO

| Action | Main WO | Duplicate WO |
| --- | --- | --- |
| Troubleshoot | ✅ Yes | ❌ No — contact the resident to set expectations only |
| Call EEC / PM | ✅ Yes | ❌ No — link the existing call (unless there is new information) |
| Dispatch a Service Provider | ✅ Yes | ❌ Never |
| Title | **Main WO - (Issue)** | **Duplicate - Main WO #[number] - (Issue)** |
| Notes | Issue, Units Reporting, Verification Method, duplicate WO numbers | Main WO number and link |
| Final status | Worked to completion | Canceled via **Take Action** |

## ❓Frequently Asked Questions

<Accordion title="Q1: What if the situation escalates to a Property Damaging / Extreme Habitability (PD/EH) category?">
  1. If a new report shows the incident now qualifies as **PD/EH**, make sure the **EEC is contacted from the Main WO** if they have not already been notified about the PD/EH situation. Refer to [How to: Identify Property Damage and Extreme Habitability Situations](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Identify-Property-Damage-and-Extreme-Habitability-Situations).
  2. Manually trigger the **"Who Ya Gonna Call"** tool from the **Action Menu** of the Main WO to get the correct contacts and call order based on time of day and scenario. Review the AI recommendation first, and verify it against the original escalation instructions displayed below it.
  3. Follow [Job Aid: PM Outbound Communication for Emergency WOs](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-PM-Outbound-Communication-for-Emergency-WOs).
  4. **Link the calls** to both the new report and the **Main WO**. Refer to [How to: Link Calls to a WO](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Link-Calls-to-a-WO).
  5. If the escalation is a **911 situation** (e.g., gas leak, fire, carbon monoxide), follow [How to: Handle 911-Severity Type Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-911-Severity-Type-Work-Orders) first.
</Accordion>

<Accordion title="Q2: Several units reported the same building-level issue, but it is NOT an emergency per the PM's intake settings. Does this SOP apply?">
  No. This SOP covers **emergency** work orders only.

  1. Handle each work order according to the PM's intake settings and the standard non-emergency process. Do **not** cancel them as duplicates.
  2. Add a note to each work order listing the **other related WO numbers** in the building so the PM can see the connection.
  3. If you're unsure, escalate to the **Operations Support Specialists** via **#ops_assistance_hub**.
</Accordion>

<Accordion title="Q3: A resident follows up (call, voicemail, SMS, or email) about the building-wide issue, but I can't identify their unit. Which work order do I use?">
  1. Search the building address without the unit number (**Step 2**) to find the **Main WO**.
  2. **If a Main WO exists:** log the follow-up on the **Main WO** (link the call or add a note/task there) per [SOP: Work Order Follow ups and Updates](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/SOP-Work-Order-Follow-ups-and-Updates). Note that the caller's unit could not be identified.
  3. **If there are multiple active WOs but no Main WO yet:** confirm the issue meets **Step 1**, set up the Main WO using **Step 3**, and log the follow-up there.
  4. If the callback number reaches the **property management office** instead of the resident, do not treat the PM office as the resident. Document the attempt on the Main WO.
</Accordion>

<Accordion title="Q4: The issue is in a common area (e.g., boiler room, hallway, fire alarm panel) and several residents reported it. How many work orders should there be?">
  **One.** A common-area issue reported by several residents is handled under a single **Main WO**, and the other reports are handled as duplicates using **Step 4**.

  1. Follow the **common area** guidance in [How to: Handle Emergency Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders): call residents for **access information and clarification only** — do not ask them to troubleshoot a common-area issue.
  2. If access information is needed to dispatch and only the PM can provide it (e.g., locked boiler room, building entry authorization), use **PM Input Needed Before Dispatch** per Scenario 2 of [Job Aid: PM Outbound Communication for Emergency WOs](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-PM-Outbound-Communication-for-Emergency-WOs).
</Accordion>

<Accordion title="Q5: A non-resident (e.g., utility company, gas company, water department) reports a building-wide issue but can't give a unit number. What do I do?">
  1. **If it is a 911 situation** (e.g., gas leak): follow [How to: Handle 911-Severity Type Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-911-Severity-Type-Work-Orders). Resident and public safety come first.
  2. **Search the building address** (**Step 2**) for an existing Main WO or related work orders. If one exists, add the caller's information to that WO as a note and link the call.
  3. **If the issue is PD/EH and there is no related WO:** the PM must be notified even without a work order. Open **Who Ya Gonna Call** from the **PM Company** or **Property** page and follow [Job Aid: PM Outbound Communication for Emergency WOs](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-PM-Outbound-Communication-for-Emergency-WOs).
  4. **If the issue is not PD/EH:** route the caller's message to the PM using **"Caller is Property Owner or Utility"** in [How to: Intake Non-Resident Requests (Non-maintenance Requests)](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Intake-Non-Resident-Requests-Non-maintenance-Requests).
  5. **On-Call customers** (app.latchel.com): the PM Outbound Communication job aid does not apply. Follow [Follow Up Guidelines for On-Call Customers (app.latchel.com)](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Follow-Up-Guidelines-for-On-Call-Customers-app-latchel-com) and escalate to the **Operations Support Specialists** via **#ops_assistance_hub** if no unit can be identified.
</Accordion>

## 🎯 When to Break This SOP

**Do not break or deviate from this SOP on your own authority.** Escalate to the **Operations Support Specialists** via **#ops_assistance_hub**, or follow explicit instructions, if you believe an exception is necessary — for example:

- There is a safety risk to a resident (if it is a 911 situation, follow the 911 SOP immediately).
- There is a high risk of property damage, or the issue is escalating rapidly.
- You are unable to confirm a shared system (e.g., the building has multiple boilers, HVAC systems, or other infrastructure). 🔧
- Reports appear to be separate incidents, not occurring within the same outage window.
- Details are inconsistent across units, suggesting multiple distinct issues.
- The property team or Service Provider requests separate WOs.
